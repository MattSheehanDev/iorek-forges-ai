Open the skill that matches

Toy matcher. A request opens a skill when it shares a phrase with that skill’s name or description. Not a model. Token counts are characters divided by four, rounded. Not a tokenizer. No network, no API key.

Northwind Platform’s coding agent has twelve team skills installed: the deploy checklist, release notes, a read-only SQL guard, invoice PDFs, postmortems, and the rest of the engineering SOPs. The Agent Skills format puts a name and a description in YAML at the top of each SKILL.md. Startup loads those lines. The longer body, and any script or reference next to it, stays on disk until a request matches.

Monolithic dump

Every turn pastes all twelve bodies, plus every script and reference. The cafeteria question costs the same as a release. The window fills with procedures nobody asked for.

Progressive disclosure

Level 1 is the catalog, about a hundred tokens a skill, loaded at startup. Level 2 opens the matching SKILL.md body. Level 3 opens a script or a reference only when this request needs that file.

Northwind kept one platform agent. Invoices, SQL, postmortems, and the release checklist are skills on that agent. Each skill is a folder the team can review in git. A separate subagent for every SOP would multiply prompts, tools, and handoffs for work that is usually one file.

Judgment in markdown, precision in code

The skill body holds the decisions: when to roll back, what an apology may admit, when a review must not apply a migration. When the next step has to be exact, the body names a file. The agent runs that file, or copies it, instead of improvising SQL, shell flags, or PDF coordinates from the prose.

Installed skills

Twelve folders. The directory name matches the name in the YAML. Opening one here is for you. It does not change the token meter. The meter changes only when the request matches.

What a team would change

Write one skill for one workflow

Pick a job the team already repeats: cutting a release, a postmortem, a read-only revenue question. Add a folder whose name is the YAML name, with SKILL.md at the root. The description says what it does and when to use it, in the words a teammate would type. That line is the trigger. A vague “helps with releases” matches everything or nothing.

Put precision in scripts/

Leave the stop rules, the tone, and the order of operations in the markdown. Put the byte-exact step in scripts/ or the fixed skeleton in references/. The body points at the path. Northwind’s SQL skill is a judgment about which table is revenue, and a script that refuses writes. The apology skill has no script, because the work is the judgment.

function contextFor(skills, request) {
  var catalog = skills.map(function (skill) {
    return skill.name + ": " + skill.description;
  });
  var matched = skills.filter(function (skill) {
    return matches(skill, request);
  });
  return catalog.concat(matched.map(function (skill) {
    return skill.body;
  }));
}
